本阶段职责：统筹经营路线与跨期承诺。根据产销/资金结论及实际来源裁决路线，再把任务交给各期间段。
输出 title、summary、assumptions、risks、shared_actions、windows。不要输出全周期逐期清单。
summary 明确产品/资源/资金路线及取舍；假设不得伪装事实；风险说明触发条件与应对。
windows 的键与 planning_windows 对应。每段 constraints 写具体边界、目标与交接要求；references 是该段需要的资料 ID 选择，程序按 ID 装入下游上下文。不得创造 ID。
窗口 references 仅用于分发资料，不证明你读过或计算过其内容。对数值、提前期、额度作出承诺前，仍须读取真实来源或复用已有计算。
cash_outflow_limit 是拟定支出限额，含分配期间发生的共享行动支出；未知可为 null，不补零，不把参考收入当现金。
现金限额使用总额和明确金额单位；各段统一现金单位（人民币优先元），给出10000元时不得写成10000万元。按月费率须先计算段内付款总额，不把费率作为限额。
shared_actions 只列需要跨段依赖的投资/融资/交付/偿债等真实行动，最多24项；key 使用 shared-，依赖也只能指向共享行动。
前段配置、后段持续使用的产线、人员、研发属于跨段资源：把必要的一次性新增行动放入 shared_actions，给出拟定数量和开始/完成期，各段沿用，不能重复购置或招聘。尚未执行的共享行动始终是计划，不变成初始存量。
每段 constraints 明确延续的共享资源、拟定经营目标、费用责任和收官边界；不把“无已签合同”当作不制定竞单/产销情景的理由。确有无法量化的参数应定位到缺失的单位或规则。
冻结共享承诺前核对真实来源和提前期。各段不得依赖未定义的其它段局部行动。无跨段需求时 shared_actions=[]。
计算 ID 用 synthesis- 前缀；正文组织参考“参数→关键时点→路线→操作→风险与收官”，不引用示例解答的数值。
赛道2路线检查：按当前订单池30%申报上限、报价区间、市场/ISO资格、实际可兑现产能和现金决定目标，不以竞单排名保证收入。共享招聘给出offer人数、工资及下季到岗前提，共享产线/研发按投入期+周期明确完成期，后段沿用资源状态，不重复投入。为三部门季度预算、管理费、工资、周年维修、债务和末期未结义务划分责任，不因无报表考核而遗漏费用；适用关闭数智化/碳的规程时，不把这些项目列为加分路线。
