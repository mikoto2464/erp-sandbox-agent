# ERP 沙盘 Agent

Python >= 3.11 的 ERP 沙盘辅助系统，通过分步页面上传、复核题目和生成方案。当前交付读题与复核闭环，以及可切换的解题策略接口；完整经营仿真、DOCX/Excel 导出与方案答疑将在后续阶段接入。

## 启动

复制 `.env.example` 为 `.env`，先设置进入系统的访问密钥：

```dotenv
ERP_ACCESS_KEY=你自行设置的访问密钥
```

访问密钥与模型供应商的 API 密钥分别配置。没有设置 `ERP_ACCESS_KEY` 时，系统拒绝登录并显示配置提示。

安装项目依赖并启动：

```bash
uv venv --python 3.11
uv pip install --python .venv/bin/python -e .
.venv/bin/python main.py
```

已有虚拟环境时直接安装依赖。也可使用 `python -m pip install -e .`。

打开 `http://127.0.0.1:8000`。使用项目虚拟环境时执行 `.venv/bin/python main.py`。数据默认保存在 `.erp-data/erp.sqlite3`，含原始文件、解析数据、题目版本、方案和任务状态；运行不依赖 `sample/`。

登录后点击右上角“模型预设”，新增并命名配置，例如“生产主模型”“备用模型”“本地测试”。每套预设独立保存接口类型、地址、模型名称、API 密钥、输出格式与资源上限。保存新预设后点击“启用此预设”，或从顶部下拉框快捷切换，当前服务无需重启。

编辑预设可改名和更新配置；更新当前启用预设后，新任务使用新配置，其他预设仍保留。当前预设需先切换后才能删除，删除同时移除其中保存的密钥。未配置完成的预设可保存，补全模型名称与所需密钥后才能启用。同一接口留空保留其密钥，换接口类型或主机需重填；新增预设不继承其他预设的密钥。密钥只保存在服务端，不回传给浏览器。

保存预设后可点击“测试连接”，通过一条简短的 JSON 请求检查地址、鉴权、模型名与当前输出参数，测试不会修改或启用预设。通过小请求测试不等于完整题目在相同输入/输出预算内可读取。HTTP 400/422 会展示接口返回的 JSON 错误说明及已知参数建议，隐藏 API 密钥；非 JSON 错误页不回传。

任务提交时固定预设及其版本，排队、执行和读题格式修复都使用该配置；任务记录保存预设名称、版本及不含密钥的配置摘要。切换、更新或删除预设不会改变已提交任务。重新提交或重试任务采用当时启用的预设。

所有预设和启用状态写入服务端数据目录的 `model-settings.json`（版本化结构，权限 `0600`），采用原子写入；重启后仍生效，该文件存在时优先于模型环境配置。旧的单套配置自动迁移为“默认配置”；首次没有配置文件时，从环境配置创建默认预设。已有环境变量优先于 `.env`：

```dotenv
ERP_LLM_PROVIDER=openai_chat
ERP_LLM_BASE_URL=https://你的兼容接口/v1
ERP_LLM_API_KEY=你的密钥
ERP_LLM_MODEL=你的模型名称
ERP_DEFAULT_SOLVER=llm_only
```

支持以下接口类型，前端和 `ERP_LLM_PROVIDER` 使用同一配置：

| 配置值 | 请求接口 | 地址留空时使用 |
| --- | --- | --- |
| `openai_chat` | OpenAI / 兼容 Chat Completions | `https://api.openai.com/v1` |
| `openai_responses` | OpenAI Responses | `https://api.openai.com/v1` |
| `anthropic` | Claude 原生 Messages | `https://api.anthropic.com/v1` |
| `gemini` | Gemini 原生 generateContent | `https://generativelanguage.googleapis.com/v1beta` |
| `ollama` | Ollama 原生 Chat | `http://localhost:11434` |

接口地址可用基础 URL 或所选协议的完整端点，系统避免重复添加端点。DeepSeek、通义等提供 OpenAI 兼容接口的服务选 `openai_chat`，填写其对应地址和模型名；不是按模型名称推断协议。本机 Ollama 可不填 API 密钥，远程接口仍需要鉴权。

Anthropic 基础地址未带 `/v1` 时自动添加 `/v1/messages`。例如 DeepSeek 的 Anthropic 兼容地址 `https://api.deepseek.com/anthropic` 会请求 `https://api.deepseek.com/anthropic/v1/messages`。已含 `/v1` 或完整 `/messages` 的地址不会重复添加。兼容网关的强制工具输出能力需单独确认，报 `tool_choice` 不支持时可将输出格式改为 `json_object` 或 `text` 并保存、测试；应用层仍执行 JSON 契约校验。

默认 `ERP_LLM_FORMAT=json_schema`：OpenAI 请求 Schema，Claude 通过指定工具的结构化输入返回结果（不执行模型生成的工具），Gemini 设置 JSON Schema，Ollama 传入格式 Schema。模型或服务不支持 Schema 时可选 `json_object`；不支持结构化输出参数时选 `text`，只使用提示词要求 JSON，服务端继续严格校验实际响应，不保证模型一定遵从格式。OpenAI 兼容服务若不接受 `max_completion_tokens`，设置 `ERP_LLM_TOKEN_PARAMETER=max_tokens` 或在前端高级参数选择。

供应商版本和模型能力可能限制结构化输出。当前使用已安装的真实 LangChain 集成包与固定 SDK 响应验证请求和输出，真实供应商仍需联调。模型调用使用 `ChatOpenAI`（含 Responses）、`ChatAnthropic`、`ChatGoogleGenerativeAI` 和 `ChatOllama`；结构化输出通过 `with_structured_output(include_raw=True)` 完成，服务端继续检查结束状态、拒绝及业务契约。新模型可通过 LangChain 模型类接入，或实现 `LLMClient` 后在组合根注入。

预设高级参数支持“接口默认 / 关闭思考 / 开启思考”。OpenAI 兼容服务使用供应商的 `thinking` 扩展（例如 DeepSeek），不保证所有兼容服务都支持；Anthropic 显式开启思考时需设置小于输出上限的思考预算，并选择 `json_object` 或 `text`，避免强制工具与思考冲突。读题通常可先关闭思考测试。输出 Token 上限可配置至 393216、输入字符上限至 8000000、超时至 1800 秒，实际限制以接口为准；字符数不等于上下文 Token 数。截断错误展示结束原因、预算以及接口提供的输出/思考用量，不保存截断结果。现有预设保持原值，迁移不会自动提高预算或关闭思考。

服务端网络需要代理时，可在启动命令中配置标准环境变量：

```bash
HTTPS_PROXY=http://127.0.0.1:7890 HTTP_PROXY=http://127.0.0.1:7890 ALL_PROXY=http://127.0.0.1:7890 all_proxy=http://127.0.0.1:7890 NO_PROXY=localhost,127.0.0.1 .venv/bin/python main.py
```

代理应对运行服务的进程可达；容器中的 `127.0.0.1` 指向容器自身。代理环境变量配置在终端或部署环境，项目 `.env` 只接受 `ERP_` 配置。程序没有内置固定代理地址。SOCKS5 代理所需的 `socksio` 已列为项目依赖；缺少时显示明确错误，不再只提示模型参数有误。

未配置模型时可以上传和查看原文，读题与方案生成会显示配置缺口。DOCX 直接解析；旧 DOC 需要安装 LibreOffice，或替换 `DocumentConverter`。图片 OCR 暂未实现，系统会提示复核图片内的信息。

## 使用

输入访问密钥进入系统，“记住此浏览器”默认勾选，保存 30 天登录会话；取消勾选则使用浏览器会话 Cookie，服务端最长有效期为 12 小时。浏览器只保存 HttpOnly 会话 Cookie，不保存原始访问密钥。会话持久化在 `access.sqlite3`，退出或更换访问密钥后相应旧会话失效。

创建或打开项目后，按以下入口操作：

1. **上传题目**：点击或拖入多个 DOCX/DOC，等待解析，勾选本次读取的文件，可展开原文查看段落与表格。
2. **读题复核**：待确认列表中直接填写经营年数和每年期数，与其他待确认项统一处理。问题卡显示实际文字或数值，可直接填写处理说明；模型提示点“确认处理”，系统错误点“确认 / 修改”修正数据及来源。说明可留空，记录为“默认”；无原文依据的输入仍保留假设状态。单位未注明或标注“不清楚”时按无单位保存，保留数值；未知值保持 `null`。“保存并继续”一次完成保存校验并进入方案页，有剩余错误时说明原因。
3. **经营方案**：选择直接生成（单 LLM）或搜索更优方案（LLM + 蒙特卡罗）。结果按期展示操作，并分别查看暂定条件、风险和检查结果。确认题目页只显示当前数据，不提供版本选择；后台保留快照，题目调整后会提示此前计划需要重新生成。
4. **方案与表格**：已预留 Word 方案、Excel 模板上传/填写/导出及文件核对区域，当前标记待开发，操作按钮不可用。
5. **方案答疑**：已预留围绕当前计划提问的对话区域，当前标记待开发，尚不发送模型请求。

读题会核对数值、百分比/万元转换、中文数量与来源；读题和方案格式不合法时最多进行一次修复请求，方案任务显示“修复方案格式”；连续失败返回校验原因。仅移除包住整个响应的 JSON Markdown 代码块，不接受残缺 JSON、重复键或夹带其他文字的响应。求解只发送规范问题、规则和疑点，不重复发送历史原始模型响应。缺少经营周期时，在模型调用前提示补齐，不让模型猜测年数。同一项目不同时提交多次读题。来源存在不代表语义全部正确，仍需复核人员类别、时间口径、规则冲突和资料缺失。

读题区分对象名称、文字属性与数值；还款方式等按文字核对，允许清理中文排版空格。单位不明时留空，不自行猜测倍率；明确的百分比或万元仍按原文转换。例如“效率（%）”列的 `50` 保存为比例 `0.5`。分页续表在相邻无新主题、列结构和业务行模式一致时继承上表标题，其他列或无续接依据的表不能成为单位来源。查看原文显示前文、列标题、原值、适用表头和当前行，并高亮引用格；来源搜索可按对象和列标题查找。已有文档无需重新上传即可显示上下文；历史误报字段可选择正确来源并标为已知后保存校验，或重新读题采用新提示词。

项目列表和项目页面均可删除项目；确认后删除其文件、题目版本、方案和任务记录，并取消关联后台任务。未保存的读题修改在离开页面时会提示。任务进度、错误、取消和重试位于步骤下方的任务记录。

## 两种解题策略

| 模式 | 行为 | 当前能力 |
| --- | --- | --- |
| `llm_only` | LLM 提出一套结构化计划，经过统一校验，不执行随机搜索 | 已接入 Web 和后台任务；当前是结构校验后的草稿，尚未验证经营可行性 |
| `llm_monte_carlo` | LLM 给出基线与金额/数量范围，采样候选，由注入的确定性评分器检查、比较并复验最佳结果 | 搜索实现已完成并用手算评分测试；真实 ERP 评分器未实现时 Web 明确显示不可用 |

在 `api/server.py` 的 `create_workflow()` 中组装模型、解析器、求解器和存储；`create_server()` 支持注入不同 `LLMClient` 和 `PlanEvaluator`。两种模式共用 `SolveRequest` / `SolutionBundle`，方案记录策略、题目版本、种子、候选和模型响应。切换模式只改变这次请求，不改题目。

当前蒙特卡罗实现仅对固定的确定性评分情景搜索行动参数；对手/需求的多情景评估、独立样本验证和策略空间迭代尚未实现。它报告采样发现的最佳可行方案，不保证找到了真实最优点。单 LLM 模式不会绕过后续仿真校验。

## 模块与约定

`domain` 是不可变业务模型与字段校验；`application` 定义接口、结构化边界和读题/求解/流程用例；`adapters` 实现 OOXML、兼容模型接口、SQLite 和后台执行；`api` 提供可替换的 Web 适配器。角色提示词位于 `prompts/`。

数据当前采用带类别、实体 ID、字段键、类型、单位、来源与状态的规范属性结构，后续由仿真适配器转换成具体产品、产线、合同等领域模型。字段来源支持检查用于发现数值不一致，不能独自证明全部语义正确；规则表达式只登记，不执行。未知新机制需显式扩展仿真能力。

模型适配已迁移到 LangChain，SDK 负责请求序列化、鉴权、模型重试及消息解析，应用层保留结构化边界、证据校验、任务状态和经营规则。Web、OOXML 与 SQLite 继续采用标准库实现。FastAPI/Pydantic/python-docx 仍是后续适配器可选项，不作为当前运行依赖。后台执行器采用线程，后续 CPU 密集仿真应替换为进程执行器；UI 用轮询读取持久化任务进度。

部署默认为本机使用。当前采用共享访问密钥，持有密钥的使用者可以访问全部项目并管理共用模型预设，没有独立用户账号或项目所有权。当前预设切换适用于单服务进程；多进程/多实例部署需要共享存储与配置通知适配器，不会自动同步其他进程。HTTPS 部署时设置 `ERP_COOKIE_SECURE=true`；独立多用户服务还需接入账号与资源授权。任务重启后保留阶段数据并标记未完成任务失败，当前需要重新提交对应阶段，尚不支持搜索检查点恢复。转换/模型请求只能在响应或超时后检查取消。

更多设计与阶段验收见 [AGENTS.md](AGENTS.md)。

## 测试

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
node --check src/erp_agent/api/static/app.js
```

测试动态生成最小 DOCX，模型使用固定响应，不依赖样例目录、外网或密钥。使用真实 LangChain 模型类和 SDK、模拟 HTTP 响应覆盖五类接口的请求格式、鉴权、结构化结果、思考与截断诊断以及统一读题契约，预设增删改/切换、独立密钥、迁移与重启、版本冲突、原子保存失败和排队任务配置固定，以及结构解析、数值证据、有限格式修复、两种策略、任务取消、30 天会话和项目删除期间的后台写入。HTTP 测试用内存连接执行真实请求处理器，适用于禁止创建套接字的沙箱；真实端口、浏览器显示与模型供应商仍需本机联调。

开发工具配置在 `pyproject.toml`；可在可联网环境安装开发依赖并运行 Ruff 和 mypy。当前环境未能安装这些工具，因此未声称其检查已经通过。
