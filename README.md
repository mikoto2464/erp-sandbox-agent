# ERP 沙盘 Agent

Python >= 3.11 的 ERP 沙盘辅助系统，通过分步页面上传、复核题目和生成方案。当前交付读题与复核闭环，以及可切换的解题策略接口；完整经营仿真、DOCX/Excel 导出与方案答疑将在后续阶段接入。

## 启动

复制 `.env.example` 为 `.env`，先设置进入系统的访问密钥：

```dotenv
ERP_ACCESS_KEY=你自行设置的访问密钥
```

访问密钥与模型供应商的 API 密钥分别配置。没有设置 `ERP_ACCESS_KEY` 时，系统拒绝登录并显示配置提示。

安装项目依赖并启动：

```bash
uv venv --python 3.11
uv pip install --python .venv/bin/python -e .
.venv/bin/python main.py
```

已有虚拟环境时直接安装依赖。也可使用 `python -m pip install -e .`。

打开 `http://127.0.0.1:8000`。使用项目虚拟环境时执行 `.venv/bin/python main.py`。数据默认保存在 `.erp-data/erp.sqlite3`，含原始文件、解析数据、题目版本、方案和任务状态；运行不依赖 `sample/`。

登录后点击右上角“模型预设”，新增并命名配置，例如“生产主模型”“备用模型”“本地测试”。每套预设独立保存接口类型、地址、模型名称、API 密钥、输出格式与资源上限。保存新预设后点击“启用此预设”，或从顶部下拉框快捷切换，当前服务无需重启。

编辑预设可改名和更新配置；更新当前启用预设后，新任务使用新配置，其他预设仍保留。当前预设需先切换后才能删除，删除同时移除其中保存的密钥。未配置完成的预设可保存，补全模型名称与所需密钥后才能启用。同一接口留空保留其密钥，换接口类型或主机需重填；新增预设不继承其他预设的密钥。密钥只保存在服务端，不回传给浏览器。

保存预设后可点击“测试连接”，通过一条简短的 JSON 请求检查地址、鉴权、模型名与当前输出参数，测试不会修改或启用预设。通过小请求测试不等于完整题目在相同输入/输出预算内可读取。HTTP 400/422 会展示接口返回的 JSON 错误说明及已知参数建议，隐藏 API 密钥；非 JSON 错误页不回传。

任务提交时固定预设及其版本，排队、执行和读题格式修复都使用该配置；任务记录保存预设名称、版本及不含密钥的配置摘要。切换、更新或删除预设不会改变已提交任务。重新提交或重试任务采用当时启用的预设。

所有预设和启用状态写入服务端数据目录的 `model-settings.json`（版本化结构，权限 `0600`），采用原子写入；重启后仍生效，该文件存在时优先于模型环境配置。旧的单套配置自动迁移为“默认配置”；首次没有配置文件时，从环境配置创建默认预设。已有环境变量优先于 `.env`：

```dotenv
ERP_LLM_PROVIDER=openai_chat
ERP_LLM_BASE_URL=https://你的兼容接口/v1
ERP_LLM_API_KEY=你的密钥
ERP_LLM_MODEL=你的模型名称
ERP_DEFAULT_SOLVER=llm_only
```

支持以下接口类型，前端和 `ERP_LLM_PROVIDER` 使用同一配置：

| 配置值 | 请求接口 | 地址留空时使用 |
| --- | --- | --- |
| `openai_chat` | OpenAI / 兼容 Chat Completions | `https://api.openai.com/v1` |
| `openai_responses` | OpenAI Responses | `https://api.openai.com/v1` |
| `anthropic` | Claude 原生 Messages | `https://api.anthropic.com/v1` |
| `gemini` | Gemini 原生 generateContent | `https://generativelanguage.googleapis.com/v1beta` |
| `ollama` | Ollama 原生 Chat | `http://localhost:11434` |

接口地址可用基础 URL 或所选协议的完整端点，系统避免重复添加端点。DeepSeek、通义等提供 OpenAI 兼容接口的服务选 `openai_chat`，填写其对应地址和模型名；不是按模型名称推断协议。本机 Ollama 可不填 API 密钥，远程接口仍需要鉴权。

Anthropic 基础地址未带 `/v1` 时自动添加 `/v1/messages`。例如 DeepSeek 的 Anthropic 兼容地址 `https://api.deepseek.com/anthropic` 会请求 `https://api.deepseek.com/anthropic/v1/messages`。已含 `/v1` 或完整 `/messages` 的地址不会重复添加。兼容网关的强制工具输出能力需单独确认，报 `tool_choice` 不支持时可将输出格式改为 `json_object` 或 `text` 并保存、测试；应用层仍执行 JSON 契约校验。

默认 `ERP_LLM_FORMAT=json_schema`：OpenAI 请求 Schema，Claude 通过指定工具的结构化输入返回结果（不执行模型生成的工具），Gemini 设置 JSON Schema，Ollama 传入格式 Schema。模型或服务不支持 Schema 时可选 `json_object`；不支持结构化输出参数时选 `text`，只使用提示词要求 JSON，服务端继续严格校验实际响应，不保证模型一定遵从格式。OpenAI 兼容服务若不接受 `max_completion_tokens`，设置 `ERP_LLM_TOKEN_PARAMETER=max_tokens` 或在前端高级参数选择。

供应商版本和模型能力可能限制结构化输出。当前使用已安装的真实 LangChain 集成包与固定 SDK 响应验证请求和输出，真实供应商仍需联调。模型调用使用 `ChatOpenAI`（含 Responses）、`ChatAnthropic`、`ChatGoogleGenerativeAI` 和 `ChatOllama`；结构化输出通过 `with_structured_output(include_raw=True)` 完成，服务端继续检查结束状态、拒绝及业务契约。新模型可通过 LangChain 模型类接入，或实现 `LLMClient` 后在组合根注入。

预设高级参数支持“接口默认 / 关闭思考 / 开启思考”。OpenAI 兼容服务使用供应商的 `thinking` 扩展（例如 DeepSeek），不保证所有兼容服务都支持；Anthropic 显式开启思考时需设置小于输出上限的思考预算，并选择 `json_object` 或 `text`，避免强制工具与思考冲突。读题通常可先关闭思考测试。输出 Token 上限可配置至 393216、输入字符上限至 8000000、超时至 1800 秒，实际限制以接口为准；字符数不等于上下文 Token 数。截断错误展示结束原因、预算以及接口提供的输出/思考用量，不保存截断结果。现有预设保持原值，迁移不会自动提高预算或关闭思考。

服务端网络需要代理时，可在启动命令中配置标准环境变量：

```bash
HTTPS_PROXY=http://127.0.0.1:7890 HTTP_PROXY=http://127.0.0.1:7890 ALL_PROXY=http://127.0.0.1:7890 all_proxy=http://127.0.0.1:7890 NO_PROXY=localhost,127.0.0.1 .venv/bin/python main.py
```

代理应对运行服务的进程可达；容器中的 `127.0.0.1` 指向容器自身。代理环境变量配置在终端或部署环境，项目 `.env` 只接受 `ERP_` 配置。程序没有内置固定代理地址。SOCKS5 代理所需的 `socksio` 已列为项目依赖；缺少时显示明确错误，不再只提示模型参数有误。

未配置模型时可以上传和查看原文，读题与方案生成会显示配置缺口。DOCX 直接解析；旧 DOC 需要安装 LibreOffice，或替换 `DocumentConverter`。PDF 使用 pdfplumber 提取文字和表格并保留页码；扫描件当前未启用 OCR，可改用手动题目或补充输入。XLS 使用 xlrd 读取工作表、行列、合并区域与百分比格式，不执行宏或重算公式；已有公式结果来自文件中保存的值。图片 OCR 暂未实现，系统会提示复核图片内的信息。

读题按“资料解析/分批 → 一次整理参数与规则 → 合并与必要的关联复核 → 来源校验”执行。小表或短章节一次格式化，不为每个条目单独设角色；长资料使用 LangChain 切分，保留完整行、表头、原行列与来源，重复表头按组共享。紧凑模型输出由 Python 转为完整规范数据，始终校验来源、周期及冲突；同实体跨批次关联或已有争议才追加 LLM 复核，不重复检查普通同批条目。默认每请求含提示词/Schema预留不超过 12000 字符，每批最多 16 行/段，并发 2；字符上限优先，可设置 `ERP_READER_MAX_REQUEST_CHARS`、`ERP_READER_MAX_BATCH_UNITS`、`ERP_READER_CONCURRENCY`（1–4）。字符数不等于 Token 数，实际输出预算受模型预设限制，思考配置保持生效。

504、超时或输出截断时自动拆小失败批次，最小批瞬时失败最多再试一次。格式错误仅修当前批一次，仍失败按完整行拆小；最小片段无法规范化则保留原文和明确的人工核对项，其余正常条目继续。传输故障持续失败则停止且不保存题目快照，读题禁用 SDK 内部重试以避免重复等待。任务记录显示提取进度、拆批和重试。已成功批次通过 LangGraph SQLite 检查点持久化，输入、模型预设和提示词不变时，手动重试或重启后可复用；修改输入/配置后重新提取。取消后不再发起后续请求，在途请求结束前任务可能仍等待。

Reader、Solver、Mapper 共用记忆端口。短期记忆保存当前任务要求、批次结果与未经确认的命名线索；长期记忆保存项目/题目版本下的可用事实、规则与已处理说明，采用 BM25 本地检索相关条目，不增加 Embedding 模型请求。已确认规范题目、方案数值和本次用户要求优先，记忆不覆盖冲突或作为新的数值来源。重新读题不继承旧版本事实，项目删除清除记忆；不跨项目共享。短期与长期记忆保存在同一个 `erp.sqlite3`，包含业务内容，随项目数据管理。

## 前端开发

前端采用 Vue 3、TypeScript、Vue Router 和 Vite。源码在 `web/src/`，共享组件、步骤页面、状态逻辑和 API 类型分别维护。仓库包含编译后的静态资源，按上述 Python 命令启动即可使用，无需另外启动 Node 服务。

修改前端时使用 Node >= 22.12：

```bash
npm --prefix web ci
npm --prefix web run dev
```

同时保持 Python 后端运行在 8000，访问 Vite 输出的开发地址（默认 `http://localhost:5173`）；`/api` 自动代理到后端。修改后构建：

```bash
npm --prefix web run build
```

该命令先检查 TypeScript，再生成 `src/erp_agent/api/static/` 中的页面、脚本和样式。提交时包含前端源码、锁文件和生成资源；不要直接修改静态构建文件。项目与步骤使用 Hash 路由，兼容已有项目地址和 F5 刷新。

## 服务器运行

仅在明确要求部署时更新生产环境。服务使用 [deploy/erp-sandbox-agent.service](deploy/erp-sandbox-agent.service)，监听 `0.0.0.0:8000`；域名、HTTPS 和转发由部署者配置。

代码按版本放在 `/opt/erp-sandbox-agent/releases/`，`/opt/erp-sandbox-agent/current` 指向当前版本，每版使用自己的虚拟环境。运行用户为 `erp-agent`，数据与模型预设保存在 `/var/lib/erp-sandbox-agent/`，服务配置在 `/etc/erp-sandbox-agent/erp.env`，不随代码更新覆盖。配置文件权限为 `0600`，可配置：

```dotenv
ERP_HOST=0.0.0.0
ERP_PORT=8000
ERP_DATA_DIR=/var/lib/erp-sandbox-agent
ERP_ACCESS_KEY=自行设置
```

通过 systemd 管理服务，开机自启并在进程异常退出后重启：

```bash
systemctl status erp-sandbox-agent
systemctl restart erp-sandbox-agent
journalctl -u erp-sandbox-agent -n 50 --no-pager
```

先安装新版依赖并校验配置，再切换 `current` 和重启服务；保留旧版本便于回退。服务器需 Python >= 3.11、venv 和 LibreOffice Writer（用于 DOC 转换）。上传代码不包含 `sample/`、本地项目数据库或 SSH 凭据。

## 使用

输入访问密钥进入系统，“记住此浏览器”默认勾选，保存 30 天登录会话；取消勾选则使用浏览器会话 Cookie，服务端最长有效期为 12 小时。浏览器只保存 HttpOnly 会话 Cookie，不保存原始访问密钥。会话持久化在 `access.sqlite3`，退出或更换访问密钥后相应旧会话失效。

创建或打开项目后，按以下入口操作：

1. **上传题目**：点击或拖入多个 DOCX/DOC/PDF/XLS，等待解析，勾选本次读取的文件。每个文件旁可填写说明，例如“订单数量不得超过此详单”；下方可输入补充内容和限制，也可在“手动输入题目”直接粘贴正文，不上传文件也能读取。点“保存输入”保留填写内容，点“读取题目”会先自动保存；手动题目输入直接显示；点击各文件旁的“预览”，可在弹窗查看解析后的正文、表格、页码与提示。
2. **读题复核**：经营周期默认 4 年、每年 4 季（16 期），无需手动确认；题目明确规定其他周期时采用对应值，特殊情况可在题目数据中修改并保存。待确认只显示真实冲突或无效周期。问题卡显示实际文字或数值，可针对上方问题独立填写答复，已有提取/转换说明另行展开查看；模型提示点“确认处理”，系统错误点“确认 / 修改”修正数据及来源。一般答复可留空，记录为“默认”；计息疑点需选用口径或填写回答，提供“整个期限总利率”与“暂不清楚”快捷填写，随后确认并保存。无原文依据的输入仍保留假设状态。单位未注明或标注“不清楚”时按无单位保存，保留数值；未知值保持 `null`。“保存并继续”一次完成保存校验并进入方案页，有剩余错误时说明原因。
3. **经营方案**：选择直接生成（单 LLM）或搜索更优方案（LLM + 蒙特卡罗）。直接生成可选择“保守 / 平稳 / 激进 / 其他”，默认平稳，选其他后填写经营偏好；可上传 XLSX/XLS 预算空表，解析完成后选择参与规划的模板（最多 3 份），旁边点“预览”查看工作表。方案按年/季展示操作，附模板预算条目、暂定条件、风险和检查结果。生成后在“调整这份方案”输入修改要求并生成下一版，上方基调与所选模板同样生效；历史方案保留，可从下拉框选择并继续调整。模板用于明确规划条目，可在下一步核对映射并导出 Excel 草稿；单 LLM 金额仍为未经仿真验证的草稿。题目调整后需按当前题目重新生成。
4. **方案与表格**：选择方案，生成并下载 Word 方案或标准逐季操作 Excel。填写自有空表时点“准备填写”，默认显示待处理项，可按工作表和状态筛选；点“预览填写结果”在原表结构查看拟填数据与待确定输入。无需修改时直接“确认填写”，问题条目点“查看 / 修改”核对来源与说明，随后“填写并生成 Excel”。空表仅在经营方案处上传、选择并参与生成，此页只显示当前方案使用的模板；更换空表需重新生成方案。填表 Agent 根据模板核对已规划预算，已有值直接引用方案预算，不能新增未规划输入、遗漏预算或修改已给值。公式格和已有数据不列入待填写条目，导出时逐格检查保持原样；缺少依据的输入项留空说明。大模板按工作表分批分析；旧模板重新上传可取得新增结构信息，旧方案缺少模板预算时需返回经营方案按表重新生成。未确定项目保留为空；导出不覆盖原模板，附方案编号和填写说明。文件按方案保存，任务侧栏显示生成进度，完成后在“下载文件”取得。当前无经营财务仿真，导出为草稿；公式重算单独标明状态。XLS 填写需 LibreOffice，未安装时请另存 XLSX 上传。
5. **方案答疑**：已预留围绕当前计划提问的对话区域，当前标记待开发，尚不发送模型请求。

读题会核对数值、百分比/万元转换、中文数量与来源；读题和方案格式不合法时最多进行一次修复请求，方案任务显示“修复方案格式”；方案连续失败返回校验原因；读题持续 JSON/契约/来源错误拆小至单行后转为有定位的人工核对，保留已提取的正常内容。仅移除包住整个响应的 JSON Markdown 代码块，不接受残缺 JSON、重复键或夹带其他文字的响应。求解只发送规范问题、规则和疑点，不重复发送历史原始模型响应。未提供周期时由服务端补入用户授权的默认值，并记录系统默认来源；无效值或真实冲突在模型调用前要求修正。同一项目不同时提交多次读题。来源存在不代表语义全部正确，仍需复核人员类别、时间口径、规则冲突和资料缺失。

读题区分对象名称、文字属性与数值；还款方式等按文字核对，允许清理中文排版空格。单位不明时留空，不自行猜测倍率；明确的百分比或万元仍按原文转换。例如“效率（%）”列的 `50` 保存为比例 `0.5`。分页续表在相邻无新主题、列结构和业务行模式一致时继承上表标题，其他列或无续接依据的表不能成为单位来源。查看原文按文件与表格分组显示完整原表，续表同时展示适用表头所在表；橙色标出待核对格，蓝色标出引用表头或对象，并展示当前字段及转换方式；来源搜索可按对象和列标题查找。已有文档无需重新上传即可显示上下文。

融资/贴现表同时给出期限和利率、未明确其他计息口径时，按用户默认采用对应完整期限的总利率，不重复要求年/季利率确认；新增计息/贴息口径字段记录 `term_total`。例如收款期 4 季、贴息 8% 是整个 4 季的 0.08，不再乘 4。原文另有规定时优先，付款频率与计息口径分别处理，不自行补分摊规则。旧疑点可直接回答并确认，重新读取使用新提示词。用户确认的答复随题目保存并传给方案生成，保留原数值及转换依据。

待确认列表只列实际缺失、冲突或业务含义尚未明确的内容。已采用默认/假设值保留在数据及方案说明中，不反复要求确认；已有有效经营周期也不重复显示输入卡。加载题目和生成方案时会重新校验旧结果，可证实为系统误报且内容未修改的条目自动恢复，无需重读或调用模型；用户修改和真实争议仍保留，历史快照不被改写。

手动题目、补充内容及文件说明作为独立证据随每次读题保存。修改输入后须重新读取，历史题目与方案继续绑定原输入；订单详单默认作为待竞订单池，不要求额外确认其用途；前端在“待竞订单池”分类中展示，按行保留数量上限、参考价、交货期和账期等原文数据。原文或文件说明明确为已签合同、市场调研等特殊用途时按说明处理；真实冲突或具体竞单规则缺失仍提示，数量上限不代表本队必得订单。已有快照保留原分类与记录，重新读取时使用新口径。当前仅将这些限制交给模型提取并保留，真实经营约束仍等待仿真内核实现。

题目文件和预算空表旁均有“删除”，解析中或失败的上传也可删除；确认后取消关联在途任务并清除选择。删除题目文件会去除文件说明并要求重新读题，其他未保存的补充内容保留。已用于历史题目/方案的资料留作内部归档，历史导出可继续使用；未引用的文件实际删除。

项目列表和项目页面均可删除项目；确认后删除其文件、题目版本、方案和任务记录，并取消关联后台任务。未保存的题目输入或读题修改在离开页面时会提示。五步导航位于固定顶栏，当前项目、步骤和题目复核标签保存在地址中，刷新后恢复当前位置。顶部“任务”打开侧栏，可查看进度、错误、取消和重试，点击左侧空白即可关闭。所有弹窗也支持点遮罩或按 Escape 关闭，带简短进出动画。任务完成、失败、取消或需要确认时通过左上角自动淡出的 toast 提醒，无关闭按钮，并提供结果或任务详情入口。模型选择与复核动作使用统一控件样式。后台完成不会自动切换步骤，刷新不会重复提醒历史任务。

## 两种解题策略

| 模式 | 行为 | 当前能力 |
| --- | --- | --- |
| `llm_only` | LLM 提出一套结构化计划，经过统一校验，不执行随机搜索 | 已接入 Web 和后台任务；当前是结构校验后的草稿，尚未验证经营可行性 |
| `llm_monte_carlo` | LLM 给出基线与金额/数量范围，采样候选，由注入的确定性评分器检查、比较并复验最佳结果 | 搜索实现已完成并用手算评分测试；真实 ERP 评分器未实现时 Web 明确显示不可用 |

在 `api/server.py` 的 `create_workflow()` 中组装模型、解析器、求解器和存储；`create_server()` 支持注入不同 `LLMClient` 和 `PlanEvaluator`。两种模式共用 `SolveRequest` / `SolutionBundle`，方案记录策略、题目版本、种子、候选和模型响应。切换模式只改变这次请求，不改题目。

当前蒙特卡罗实现仅对固定的确定性评分情景搜索行动参数；对手/需求的多情景评估、独立样本验证和策略空间迭代尚未实现。它报告采样发现的最佳可行方案，不保证找到了真实最优点。单 LLM 模式不会绕过后续仿真校验。

## 模块与约定

`domain` 是不可变业务模型与字段校验；`application` 定义接口、结构化边界和读题/求解/流程用例；`adapters` 实现 OOXML、兼容模型接口、SQLite 和后台执行；`api` 提供可替换的 Web 适配器。角色提示词位于 `prompts/`。

数据当前采用带类别、实体 ID、字段键、类型、单位、来源与状态的规范属性结构，后续由仿真适配器转换成具体产品、产线、合同等领域模型。字段来源支持检查用于发现数值不一致，不能独自证明全部语义正确；规则表达式只登记，不执行。未知新机制需显式扩展仿真能力。

模型适配已迁移到 LangChain，SDK 负责请求序列化、鉴权、模型重试及消息解析，应用层保留结构化边界、证据校验、任务状态和经营规则。前端采用 Vue 3 + TypeScript；HTTP 服务、OOXML 与 SQLite 继续采用标准库实现。FastAPI/Pydantic/python-docx 仍是后续适配器可选项，不作为当前运行依赖。后台执行器采用线程，后续 CPU 密集仿真应替换为进程执行器；UI 用轮询读取持久化任务进度。

部署默认为本机使用。当前采用共享访问密钥，持有密钥的使用者可以访问全部项目并管理共用模型预设，没有独立用户账号或项目所有权。当前预设切换适用于单服务进程；多进程/多实例部署需要共享存储与配置通知适配器，不会自动同步其他进程。HTTPS 部署时设置 `ERP_COOKIE_SECURE=true`；独立多用户服务还需接入账号与资源授权。任务重启后保留阶段数据并标记未完成任务失败，当前需要重新提交对应阶段，尚不支持搜索检查点恢复。转换/模型请求只能在响应或超时后检查取消。

更多设计与阶段验收见 [AGENTS.md](AGENTS.md)。

开发工具配置在 `pyproject.toml`，可安装开发依赖运行 Ruff 和 mypy；检查按实际改动选择，不代表全仓库已通过所有静态检查。

模型预设支持“优先级”“最大并行请求”“参与多模型协作”及可选“能力说明”。当前启用预设始终参与，其他模型勾选协作后加入任务模型池；数字越大越优先。最高优先级模型担任主 Agent，读取需要分配的子任务实际内容样本、修复情况、模型能力说明与当前负载，评估难度并给出执行模型和可替代模型。任务不按角色固定分配，困难提取也可交给主模型；Python 校验候选范围和输入容量，并在共享额度内执行或等待。建议主推理模型优先级 200、轻量模型 100，再按供应商额度设置并行数。主 Agent 的分配请求也计入额度，多模型需额外进行有界分配请求；同表普通数据经主 Agent 判断为简单且授权后，可复用候选分配，最多 8 次调用后重新评估，额度每次实时检查。并发同类批次共享评估，修复、复杂任务或换表重新分配；单模型直接执行。额度在同一服务全部任务间共享，任务提交后模型目录固定；连接测试不占业务调度额度，多进程之间尚不共享计数。

XLS 数值使用 Excel 的 15 位有效数字，避免数量出现 `4050.0000000000005` 之类存储尾差。此前已上传的 XLS 点击重新读题即可采用新解析结果，无需删除重传。无法可靠解析的模型字段会列出原值、对象与原文，用户可修改值和类型，或明确标注无/不清楚，其他正常条目保留。

任务侧栏已扩宽，点“展开处理详情”查看主 Agent 的难度判断与分配依据、分配时的模型负载，以及子角色、实际执行模型、文件与行范围、等待额度、重试及提取数量。同表授权复用与调度失败后的保守回退均明确显示。展示全部在途任务和最近 80 条结束明细，服务端保留最多 1000 条明细，题目数据和方案仍独立保存。新增设置只影响后续任务；日常修改不自动部署。
